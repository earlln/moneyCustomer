================================================================
  금전 대고객 작업 분류 - 배치 추론 및 학습 v2.0.0
  (Java 불필요 / exe 배포 버전)
================================================================

[개요]
  CSV 파일의 작업의뢰 내용을 읽어 아래 4개 클래스로 자동 분류하는
  배치 처리 프로그램입니다.

      0 = 비주요작업
      1 = 금전작업
      2 = 대고객작업
      3 = 금전+대고객 (둘 다)

  1, 2, 3 중 하나라도 확률이 threshold(기본 0.5) 이상이면
  "주요작업"으로 판정합니다.


[v2.0.0 핵심 변경 사항]

  1. Java(JVM) 의존성 완전 제거  ★가장 큰 변화★
     - v1.8 은 KoNLPy 의 Okt 형태소 분석기를 사용했고, 이는 내부적으로
       Java 위에서 동작하므로 JDK 설치와 JAVA_HOME 설정이 필수였습니다.
     - v2.0.0 은 C++ 로 구현된 kiwipiepy 형태소 분석기로 교체했습니다.
       Java 를 설치하지 않은 PC 에서도 그대로 실행됩니다.

  2. exe 배포
     - batch_predict.exe / train_model.exe / evaluate_model.exe
     - 파이썬을 설치하지 않은 PC 에서도 압축만 풀면 바로 실행됩니다.
     - 세 exe 는 _internal 폴더의 런타임을 공유하므로, 반드시 압축을 푼
       폴더 구조를 그대로 유지한 채 실행하세요.

  3. evaluate_model 오류 수정
     - v1.8 의 evaluate_model 은 소스 오타(file_//config 등) 때문에
       실행 즉시 NameError 로 중단되었습니다. v2.0.0 에서 수정했습니다.

  4. 정확도 측정 방식 정정  ★반드시 읽어주세요★
     - v1.8 문서의 "정확도 96.58%" 는 학습에 사용한 데이터를 그대로
       평가에 사용해 나온 값으로, 실제 성능보다 크게 부풀려진 수치입니다.
     - 학습에 쓰지 않은 검증 데이터로 다시 측정하면
           v1.8 실제 정확도 : 86.95%
       입니다. v2.0.0 은 같은 기준에서 더 높은 정확도를 냅니다
       (최신 수치는 README.md 또는 train_log.txt 참고).
     - v2.0.0 의 evaluate_model 은 검증 구간 정확도를 먼저 보여주고,
       전체 데이터 기준 수치는 "참고용(과대평가)"으로 따로 표시합니다.

  5. 영문/숫자 정보 보존
     - v1.8 은 전처리에서 한글만 남겨 시스템명의 영문 약어(HI-sPortal,
       DB, PUSH 등)가 모두 버려졌습니다. v2.0.0 은 영문·숫자도 학습에
       활용합니다.

  6. 인코딩 자동 판별
     - UTF-8 / UTF-8-SIG / CP949 / EUC-KR 을 자동으로 시도합니다.
       --encoding 옵션은 자동 판별을 덮어쓸 때만 사용하면 됩니다.

  7. 자동화 지원
     - --no-pause 옵션으로 "Enter 키를 누르세요" 대기를 생략할 수 있어
       배치 스케줄러에서 그대로 호출할 수 있습니다.
     - 정상 종료 0 / 설정·파일 오류 2 / 내부 오류 1 로 종료 코드를 구분합니다.


[stand-alone PC 설치]  ★ 파이썬·Java 미설치 PC 기준 ★

  이 배포판에는 파이썬 런타임과 형태소 사전이 모두 포함되어 있습니다.
  대상 PC 에 파이썬, Java, 인터넷 연결, 관리자 권한 중 어느 것도 필요 없습니다.

  1) zip 파일을 USB 등으로 대상 PC 에 옮깁니다.
     - 압축 상태 약 190MB, 압축 해제 후 약 330MB
     - 여유 디스크 공간 1GB 이상 권장

  2) 짧은 경로에 압축을 풉니다.  예) C:\MoneyCustomer
     ※ 바탕화면 깊은 폴더처럼 경로가 길면 Windows 경로 길이 제한(260자)에
       걸려 일부 파일이 풀리지 않을 수 있습니다.
     ※ C:\Program Files 아래는 피하세요. 결과 CSV 와 로그를 프로그램 폴더에
       기록하므로 쓰기 권한이 필요합니다.

  3) 자체점검.bat 을 더블클릭합니다.
     예시 데이터 12건이 분류되고 "[성공]" 이 표시되면 설치 완료입니다.

  설치 시 주의 사항
    - _internal 폴더는 exe 와 같은 위치에 있어야 합니다.
      exe 파일만 따로 복사하면 실행되지 않습니다.
    - 코드 서명이 없어 백신이나 SmartScreen 경고가 뜰 수 있습니다.
      사내 배포 시 예외 등록이 필요할 수 있습니다.
    - 대상 OS 는 64비트 Windows 10 이상입니다.
    - 설정·모델·입출력 파일은 "exe 가 있는 폴더" 기준으로 찾습니다.
      따라서 바로가기로 실행하거나 다른 폴더에서 실행해도 동작합니다.


[파일 구성]

  실행 파일
    batch_predict.exe    : 배치 추론
    train_model.exe      : 모델 재학습
    evaluate_model.exe   : 모델 성능 평가
    자체점검.bat         : 설치 직후 동작 확인
    _internal/           : 파이썬 런타임 · 라이브러리 · 형태소 사전
                           (삭제하거나 옮기지 마세요)

  데이터 · 설정
    features.json           : 컬럼, threshold, 파일명 등 전체 설정
    request_model.pkl       : 학습된 LightGBM 분류 모델
    request_vectorizer.pkl  : 학습된 TF-IDF 벡터라이저
    model_meta.json         : 학습 시점 정보 (토크나이저 설정, 성능 지표)
    train_20260527.csv      : 학습 데이터 20,000행
    sample_input.csv        : 동작 확인용 예시 입력 12행

  결과물 (실행 시 생성)
    output_20260527.csv     : 추론 결과
    train_log.txt           : 학습 로그
    evaluation_report.txt   : 평가 리포트


[사용 방법 - exe 버전]

  1) 입력 CSV 준비
     - 파일명   : features.json 의 files.input 설정값
     - 필수 컬럼: 작업의뢰명, 작업의뢰내용, 시스템명
                  (features.json 의 input_columns 와 정확히 일치해야 합니다)
     - 인코딩   : UTF-8 또는 CP949 (자동 판별)

  2) 폴더 주소창에 cmd 를 입력해 명령 프롬프트를 엽니다.

  3) 실행

     기본 실행 (features.json 설정값 사용)
       batch_predict.exe

     입출력 파일 직접 지정
       batch_predict.exe -i mydata.csv -o result.csv

     결과 미리보기
       batch_predict.exe --show

     인코딩 강제 지정
       batch_predict.exe --encoding cp949

     배치 스케줄러용 (대기 없이 종료)
       batch_predict.exe --no-pause

     모델 재학습
       train_model.exe

     성능 평가
       evaluate_model.exe
       evaluate_model.exe -d 별도평가데이터.csv


[사용 방법 - 파이썬 소스 버전]

  Java 설치는 필요 없습니다.

    pip install -r requirements.txt

    python batch_predict.py
    python train_model.py
    python evaluate_model.py

  exe 를 직접 빌드하려면 (Windows 에서만 가능):

    pip install -r requirements-build.txt
    pyinstaller --noconfirm --clean MoneyCustomer.spec

  결과물은 dist/MoneyCustomer/ 에 생성됩니다.


[출력 결과]

  입력 CSV 의 원본 컬럼 뒤에 다음 컬럼이 추가됩니다.

    prediction  : 예측 클래스 번호 (0, 1, 2, 3)
    label       : 예측된 분류명
    prob_0      : 비주요작업 확률 (0~1)
    prob_1      : 금전작업 확률 (0~1)
    prob_2      : 대고객작업 확률 (0~1)
    prob_3      : 금전+대고객 확률 (0~1)
    prob_major  : 주요작업일 확률 (prob_1+prob_2+prob_3)   ★v2.0.0 신규
    is_major    : 주요작업 여부 (True/False)
    major_label : 주요작업 / 비주요작업

  결과 파일은 UTF-8-SIG 로 저장되므로 엑셀에서 바로 열어도
  한글이 깨지지 않습니다.


[설정 파일 (features.json) 상세]

  1. 기본 정보
     - project_name : 프로젝트 이름
     - version      : 설정 파일 버전

  2. 데이터 컬럼 (매우 중요)
     - input_columns  : 분석에 사용할 텍스트 컬럼 목록
                        학습 데이터와 추론 데이터의 헤더가 이 설정과
                        정확히 일치해야 합니다.
     - target_column  : 정답(Label) 컬럼명. 학습·평가 시에만 사용합니다.

  3. 분류 로직
     - class_labels   : 클래스 번호에 대응하는 이름
     - major_classes  : "주요작업"으로 볼 클래스 번호 목록
     - threshold      : 주요작업 판정 확률 기준 (0.0 ~ 1.0)
     - major_rule     : 주요작업 판정 방식 (v2.0.0 신규)
                        "any" = major_classes 중 하나라도 확률이 threshold 이상
                                (v1.8 과 동일, 기본값)
                        "sum" = major_classes 확률의 합이 threshold 이상

                        "주요작업" 은 곧 "비주요작업이 아님" 이므로 확률적으로
                        옳은 쪽은 "sum" 입니다. 예를 들어 확률이
                        (0.40, 0.25, 0.20, 0.15) 이면 주요작업일 확률이 0.60
                        인데도 "any" 규칙은 비주요작업으로 판정합니다.

                        학습 데이터 20,000행 기준으로 두 규칙의 판정이 갈리는
                        행은 94건(0.47%)이며, 그중 "sum" 이 맞은 경우가 63건,
                        "any" 가 맞은 경우가 31건이었습니다.

                        기존 집계와의 연속성을 위해 기본값은 "any" 로 두었고,
                        갈리는 건수는 실행할 때마다 안내합니다. 재학습 없이
                        값만 바꾸면 즉시 반영됩니다.
     - blank_row_policy : 입력 CSV 의 빈 행 처리 (v2.0.0 신규)
                        "trailing" = 파일 끝의 빈 행만 제외. 중간의 빈 행은
                                     건너뛰지 않고 경고만 출력 (기본값)
                        "stop_at_first" = 첫 빈 행에서 처리 중단 (v1.8 과 동일)

                        v1.8 은 파일 중간에 작업의뢰명이 빈 행이 하나만 있어도
                        그 뒤 데이터가 전부 누락됐습니다. 기본값 "trailing" 은
                        이 문제를 없앴습니다. 또한 입력 컬럼이 "모두" 비었을
                        때만 빈 행으로 보므로, 제목만 비고 내용은 있는 행은
                        그대로 처리됩니다.

  4. tokenizer (v2.0.0 신규)
     - backend    : "kiwi"  = kiwipiepy 형태소 분석 (기본값, 권장)
                    "regex" = 의존성 없는 규칙 기반 분리 (정확도 낮음)
                    ※ 두 백엔드 모두 Java 를 요구하지 않습니다.
     - pos_tags   : kiwi 백엔드에서 남길 품사 태그
                    (NNG 일반명사, NNP 고유명사, NNB 의존명사,
                     SL 외국어, SH 한자, XR 어근)
     - min_length : 이 길이 미만의 토큰은 버림 (기본 2)
     - keep_latin : 영문·숫자 보존 여부 (기본 true)

     ★ 이 설정을 변경하면 반드시 train_model 로 재학습해야 합니다.
       학습 때와 다른 설정으로 추론하면 정확도가 급격히 떨어지며,
       프로그램이 model_meta.json 과 비교해 경고를 출력합니다.

  5. vectorizer / model_params (v2.0.0 신규)
     - TF-IDF 특징 수, n-gram 범위, LightGBM 하이퍼파라미터를
       재학습 없이 설정 파일에서 조정할 수 있습니다.

  6. files
     - train_data : 학습·평가용 CSV 파일명
     - input      : 추론 기본 입력 파일명
     - output     : 추론 기본 출력 파일명
     - model      : 모델 파일명
     - vectorizer : 벡터라이저 파일명


[모델 성능 평가 해석]

  evaluate_model 은 두 가지 수치를 보여줍니다.

    (1) 검증 구간(holdout) 정확도  ← 이 값이 모델의 실제 실력입니다
        학습에 사용하지 않은 20% 구간에서만 측정합니다.

    (2) 전체 데이터 정확도 (참고용)
        학습에 사용한 행이 포함되어 있어 항상 높게 나옵니다.
        v1.8 문서의 96.58% 가 바로 이 값입니다.

  주요 지표
    - 정확도(Accuracy) : 전체 중 맞힌 비율. 데이터 불균형에 취약.
    - 정밀도(Precision): 'A' 라고 예측한 것 중 실제 'A' 인 비율.
    - 재현율(Recall)   : 실제 'A' 중 'A' 라고 찾아낸 비율.
    - F1-Score         : 정밀도와 재현율의 조화 평균. 불균형 데이터에서
                         가장 객관적인 지표.
    - 혼동 행렬        : 어떤 클래스를 어떤 클래스로 착각하는지 확인.
                         (행 = 실제값, 열 = 예측값)


[자주 묻는 문제]

  Q. exe 가 실행되자마자 꺼집니다.
     A. cmd 창에서 실행하면 오류 메시지를 확인할 수 있습니다.
        _internal 폴더가 exe 와 같은 위치에 있는지 확인하세요.

  Q. 이 PC 에 파이썬이 없는데 실행되나요?
     A. 예. 파이썬 런타임이 _internal 폴더에 함께 들어 있습니다.
        Java 도 필요 없습니다. 자체점검.bat 으로 확인하세요.

  Q. 압축을 풀었는데 일부 파일이 없다고 나옵니다.
     A. 경로가 너무 길어 Windows 경로 길이 제한에 걸린 경우입니다.
        C:\MoneyCustomer 처럼 짧은 경로에 다시 풀어주세요.

  Q. 백신이 exe 를 차단합니다.
     A. 코드 서명이 없는 PyInstaller 실행 파일이라 오탐이 발생할 수 있습니다.
        사내 백신 정책에 예외 등록을 요청하세요.

  Q. "입력 컬럼을 하나도 찾을 수 없습니다" 오류가 납니다.
     A. CSV 헤더와 features.json 의 input_columns 가 다릅니다.
        오류 메시지에 CSV 의 실제 컬럼 목록이 함께 출력됩니다.

  Q. "학습 시점과 다른 토크나이저 설정" 경고가 뜹니다.
     A. features.json 의 tokenizer 설정을 학습 때와 다르게 바꾼 상태입니다.
        원래 설정으로 되돌리거나 train_model 로 재학습하세요.

  Q. 한글이 깨집니다.
     A. 입력은 자동 판별하지만, 확실하다면 --encoding cp949 로 지정하세요.
        출력은 UTF-8-SIG 이므로 엑셀에서 정상적으로 열립니다.
