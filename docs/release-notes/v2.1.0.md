# v2.1.0 — 주요작업 판정 기준을 확률 합(`sum`)으로 변경

기능 추가 없이 **주요작업 판정 기본 규칙 하나만** 바꾸는 릴리스입니다.
v2.0.0 의 나머지 동작(Java 불필요, exe 배포, 정확도, 출력 컬럼 구성)은 그대로입니다.

## 무엇이 바뀌나

`features.json` 의 `major_rule` 기본값이 `"any"` → **`"sum"`** 으로 바뀝니다.

| 규칙 | 판정 방식 |
|---|---|
| `any` (v1.8 ~ v2.0.0) | 금전·대고객·금전+대고객 확률 중 **하나라도** threshold 이상 |
| `sum` (**v2.1.0 기본값**) | 세 확률의 **합**이 threshold 이상 |

"주요작업" 은 곧 "비주요작업(0)이 아님" 이므로, 확률적으로 옳은 판정은 합을 보는 것입니다.
기존 규칙은 확률이 `(0.40, 0.25, 0.20, 0.15)` 인 행을 — 주요작업일 확률이 **0.60** 인데도 —
비주요작업으로 판정했습니다.

## 실제 영향 (학습 데이터 20,000행 기준)

| 항목 | `any` (v2.0.0) | `sum` (v2.1.0) |
|---|---|---|
| 주요작업 판정 건수 | 11,849 | **11,943** (+94) |
| 주요작업 판정 정확도 | 0.9834 | **0.9850** |

- 판정이 바뀌는 행은 **94건(0.47%)** 입니다.
- 변경 방향은 **한쪽뿐입니다: 비주요작업 → 주요작업.** 기존에 주요작업이던 행이
  비주요작업으로 바뀌는 경우는 없습니다. 즉 **놓치던 건을 더 잡는** 방향이며,
  금전·대고객 작업을 누락하지 않는 것이 중요한 업무 특성에 부합합니다.
- 바뀌는 94건 중 **63건은 실제로 주요작업**이 맞았고, 31건은 아니었습니다.

(위 수치는 모델이 학습에 사용한 행을 포함하므로, 절대값보다 두 규칙의 상대 비교로
읽어 주세요.)

## 집계에 미치는 영향

주요작업 건수가 약 **0.5% 증가**합니다. 기존 v1.8 / v2.0.0 기준으로 산출한 통계와
직접 비교할 때는 이 점을 감안하세요.

이전 기준이 필요하면 `features.json` 에서 되돌릴 수 있습니다. **재학습은 필요 없습니다.**

```json
"major_rule": "any"
```

두 규칙의 판정이 갈리는 건수는 실행할 때마다 안내되며, 주요작업 확률의 합은
`prob_major` 컬럼에서 항상 확인할 수 있습니다.
